# Task checkpoint

Write the goal and acceptance condition first. Then record current authority and source paths, completed work with evidence, decisions and approvals already given, open risks, and the exact next action. Separate observed state from intended state. Link to artifacts and original records rather than copying large content into the handoff.

Before handing off, verify that the referenced paths or URLs resolve in the receiving environment when possible. Name unavailable tools or access explicitly. If the next step could create an external effect, include the authorization boundary and idempotency check.

Resume by reading the checkpoint plus current map, then revalidate volatile status. Do not restart completed work or assume a stale checkpoint overrides a newer authoritative record. Remove or supersede the checkpoint when the outcome is complete.

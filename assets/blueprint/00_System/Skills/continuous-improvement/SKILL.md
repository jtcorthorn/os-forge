# Continuous improvement

Keep one home for each proposal and lesson. Read the owning maps, fleet and contracts; discover company proposal folders, improvement logs, central requests and partial/parked failures. A central queue alone does not prove coverage. Validate a known proposal as a sensor canary. Record inaccessible, missing and truncated inputs separately from no new work.

Identify each source revision by original-byte SHA256 and item ID. Reconcile the current target before acting: old proposals may already be resolved or retain human business dependencies. Preserve partial outcomes. A changed source reopens review; a missing source is not assumed completed. Use `scripts/discover_improvements.py` when an exact byte-mounted root exists, or a supported original-byte connector with explicit coverage/cursors.

Prioritize an observed operational blocker and define one acceptance check, allowed write scope and recovery path. Reuse the existing executor, immutable work IDs, preimage archive and receipts. Byte-read/hash checks do not grant authority. Prefer deterministic transfer/calculation and model judgment for ambiguity. Keep one writer per target; a reread is not an atomic distributed lock. Uncertain effects are reconciled against actual targets before retrying.

Each run has a real trigger, authoritative inputs, accountable owner, allowed actions, output, failure route and stop. A useful default is at most three reversible changes, five substantive reviews and twenty minutes, adapted by the owner before activation. Record attempts separately from verified results. Stop an unchanged failure after three attempts on the same revision until a meaningful dependency changes. Monitor only actionable failures or completed improvements, remaining quiet for unchanged state.

After a useful correction, save one source-linked lesson in its owning log, apply a low-risk method/retrieval improvement within the approved boundary, replay the original failed case and check an unaffected case. File a policy, permission, business-gate or executor change as a concrete proposal rather than granting self-modification. Lessons do not grant authority.

Claim configured, executed, verified and runtime-adopted states separately. Test a recurring process end to end on the actual host before calling it production-ready. If a public reusable package is explicitly authorized, transfer only neutral methods and verified changes, with a concise changelog; keep original/private evidence in the owner's OS. Existing recipient installations are independent of a repository update. The owner can pause the trigger or deployment state; open-ended learning consists of bounded, stoppable runs.

## Feed a reusable package

At each verified improvement, including a small route or wording fix, ask whether the correction prevents a repeatable failure for another owner. Keep the original item, source hash, decision and acceptance evidence in its owning domain. A fleet evolution note is another owning-domain source, not a separate publication queue. Review it through the same discovery and reconciliation cycle as other proposals and lessons.

If the correction is transferable, write the smallest neutral change in the reusable package's editable source. Remove private names, paths, accounts, business facts and original payloads; preserve the behavior and its limits. Replay the failure with synthetic inputs, check an unaffected case when behavior changes, and add one concise changelog entry. Build the package's verified snapshot only after those checks pass. The publication worker consumes that snapshot under its own authorization and controls; a source note or local test alone does not prove publication or adoption by an existing recipient.

If the correction is private, already covered, unverified or requires a policy, permission or business decision, record that disposition with the owning item. Do not create a public candidate merely to show activity. A changed source revision reopens the assessment, while an unchanged no-transfer decision does not require repeated review.

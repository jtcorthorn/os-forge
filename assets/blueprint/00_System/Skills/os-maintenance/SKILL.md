# OS maintenance

Read the root map and owning domain contract. Define the user-visible failure or improvement and the smallest acceptance check. Inventory the affected paths, references, generated files, and installed consumers before editing. A local copy is not necessarily the active source.

Use a single writer for the active scope. Preserve originals and version deliverables before replacement. For a move, identify inbound references, check case-folded destination collisions, copy and verify content, update active references, then retire the old path only within the user's authority. Do not hand-edit generated indexes; run their generator.

Verify the smallest meaningful result in the environment where it matters. Distinguish local file integrity, runtime discovery, actual use, cloud sync, and recipient access. Record source, date, status, and unresolved limits in the owning project history. Stop once the acceptance check passes; avoid broad audits that do not affect the decision.

Read [references/maintenance-check.md](references/maintenance-check.md) for a move or runtime change.

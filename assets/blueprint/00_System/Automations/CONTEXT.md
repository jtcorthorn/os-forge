# Bounded automation

## Inputs
A recurring task requested by the owner and a real available executor.

## Work
Use a loop-design skill. Define trigger, authoritative input, item ID, permitted actions, owner, retry/cost limits, duplicate prevention, output, failure route and stop condition.

## Outputs
Approved spec using ../../_templates/automation/AUTOMATION.md; activation receipt only after executor verification.

## Human boundary
A spec is not a running job. Activate or expand only when authorized. No news and failed collection are different states.

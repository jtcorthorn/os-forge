# Role card
State: prepared. Runtime evidence: none.
Role ID and optional display name: fill from the actual responsibility.
Accountable human: name or unknown; virtual role grants no decision rights.

## Job
Purpose and one concrete task this role owns.
Checks first: the evidence/constraint that distinguishes this specialist.

## Context and boundaries
Read: exact owning map, contract, source paths and relevant skill entry.
Write: exclusive output paths within the authorized domain.
Excluded: unrelated companies, personal/sensitive domains and private management mounts.
Allowed actions: actual current authorization.
Escalate/stop: unknown authority, missing critical source, violated acceptance or exhausted budget.

## Outputs and handoffs
Deliverable, source locators and acceptance evidence.
Upstream/downstream roles and exact return channel/artifact.
Model/executor policy: required capability; selected available model only when verified.
Runtime record: host, date, probe/output path and known limitations.

## Required skill selection
List task -> canonical skill/method -> host/tool dependency -> acceptance check. Require only the applicable route, preserve brand/voice and access boundaries, and distinguish prepared sources from installed and tested runtime capability.
